# Nexa Digital — وكالة رقمية / Digital Agency Website

موقع ولوحة تحكم كاملة لوكالة Nexa Digital، مبني بـ Next.js (App Router) وTypeScript وTailwind CSS،
مع دعم كامل للعربية (RTL، الافتراضية) والإنجليزية (LTR)، وقاعدة بيانات SQLite جاهزة للعمل فورًا.

---

## 1. التشغيل محليًا (Local setup)

**المتطلبات:** Node.js 18+ (يفضل 20+) و npm.

```bash
# 1. تثبيت الحزم
npm install

# 2. إعداد متغيرات البيئة
cp .env.example .env
# عدّل القيم داخل .env حسب الحاجة (خصوصًا ADMIN_EMAIL و ADMIN_PASSWORD و AUTH_SECRET)

# 3. تشغيل بيئة التطوير
npm run dev
```

افتح `http://localhost:3000` — سيُحوَّلك تلقائيًا إلى `http://localhost:3000/ar`.

عند أول تشغيل، يتم إنشاء قاعدة بيانات SQLite تلقائيًا في `db/nexa.sqlite` مع بيانات تجريبية
(4 خدمات، 10 أسئلة شائعة، إعدادات افتراضية) وحساب مدير واحد، دون أي إعداد إضافي.

---

## 2. حساب المدير (Admin account)

بيانات الدخول الافتراضية (من `.env`):

- الرابط: `/admin/login`
- البريد: القيمة في `ADMIN_EMAIL` (افتراضيًا `admin@nexadigital.com`)
- كلمة المرور: القيمة في `ADMIN_PASSWORD` (افتراضيًا `ChangeMe123!`)

**⚠️ مهم:** غيّر `ADMIN_EMAIL` و`ADMIN_PASSWORD` في `.env` **قبل** أول تشغيل في الإنتاج (تُستخدم فقط
عند إنشاء قاعدة البيانات لأول مرة). لإنشاء حساب مدير إضافي أو تغيير كلمة المرور لاحقًا، أضِف صفًا جديدًا
في جدول `users` (باستخدام `hashPassword` من `lib/auth.ts`).

جلسة الدخول محفوظة في كوكي HTTP-only موقّع بـ JWT (`AUTH_SECRET`)، صالحة لمدة 7 أيام.

**ملاحظة على الإنتاج:** الكوكي يُرسَل بخاصية `Secure`، أي أنه يعمل فقط عبر HTTPS. عند اختبار نسخة
الإنتاج محليًا (`npm run build && npm run start`) عبر `http://localhost`، لن يُحفظ الكوكي في المتصفح
الحقيقي — استخدم `npm run dev` للاختبار المحلي، أو انشر المشروع فعليًا حيث يكون HTTPS مفعّلًا تلقائيًا
(Vercel مثلًا).

---

## 3. إضافة خدمة جديدة (بدون كتابة كود)

1. سجّل الدخول إلى `/admin` → **الخدمات** → **إضافة خدمة**.
2. املأ `slug` (بالإنجليزية، بدون مسافات، مثل `seo-optimization`)، الاسم والوصف بالعربية والإنجليزية،
   المميزات (سطر واحد لكل ميزة)، التصنيف، والأيقونة (انظر القائمة أدناه).
3. اضبط الحالة على **منشورة** لتظهر في الموقع، أو اتركها **مخفية** لحفظها كمسودة.
4. احفظ — ستظهر الخدمة تلقائيًا في الصفحة الرئيسية وصفحة الخدمات وصفحتها الخاصة، بدون أي تعديل على الكود.

**أسماء الأيقونات المتاحة حاليًا:** `Globe, Smartphone, Palette, PenLine, Search, Share2, Megaphone,
Languages, Sparkles, Server, ShoppingCart, Wrench, Bot`. لإضافة أيقونة جديدة، أضِفها في `lib/icons.tsx`
(من مكتبة `lucide-react`).

خدمة "كتابة المحتوى" موجودة مسبقًا لكنها **مخفية بشكل افتراضي** — فعّلها من **الإعدادات** →
"تفعيل خدمة كتابة المحتوى"، كما طُلب في المواصفات.

---

## 4. تغيير بيانات التواصل والإعدادات العامة

من `/admin/settings`: اسم الموقع، البريد، الهاتف، واتساب (مع تفعيل/تعطيل الزر العائم)، العنوان،
روابط التواصل الاجتماعي، ألوان الموقع، ومعطيات SEO (العناوين والأوصاف بكلتا اللغتين، Google Analytics ID).

من `/admin/content`: تعديل العنوان الرئيسي (Hero) المخزَّن في قاعدة البيانات. باقي نصوص الموقع
(الأزرار، قسم "لماذا نحن"، خطوات "كيف نعمل"، الفوتر...) منظّمة في ملفين منفصلين حتى تبقى الترجمة
مركزية وسهلة التعديل دفعة واحدة:

- `lib/i18n/ar.json`
- `lib/i18n/en.json`

عدّل النص المطلوب في كلا الملفين وأعد بناء المشروع (أو أعد تشغيله في وضع dev، إذ يُحمَّل تلقائيًا).

## 5. الأقسام الأخرى في لوحة التحكم

- **المشاريع:** إضافة/تعديل/حذف، تحديد إن كان المشروع تجريبيًا (`is_demo`) — يظهر عندها وسم واضح
  للزوار بدلًا من نسبته زورًا لعميل حقيقي، حسب طلب المواصفات.
- **الأسئلة الشائعة:** إضافة/تعديل/حذف/ترتيب/تفعيل-تعطيل.
- **طلبات عروض الأسعار:** جدول كامل بكل الطلبات، فتح التفاصيل، تغيير الحالة (جديد → قيد المراجعة →
  تم التواصل → قيد التنفيذ → مكتمل/ملغى)، إضافة ملاحظات داخلية، حذف، وتصدير الكل كملف CSV.
- **الرسائل:** رسائل نموذج "تواصل معنا"، مع تغيير الحالة (جديدة/مقروءة/تم الرد) وحذف.

جميع نقاط الوصول (API routes) الخاصة بالتعديل (POST/PATCH/DELETE) محمية بجلسة المدير، وتتحقق من
صحة المدخلات عبر `zod`، وتُطبِّق حدًا أقصى لعدد الطلبات (rate limiting) على النماذج العامة.

## 6. النشر (Deployment)

### على Vercel (الأسهل)

1. ارفع المشروع إلى مستودع GitHub/GitLab.
2. استورده في vercel.com كمشروع جديد.
3. أضف متغيرات البيئة من `.env.example` في إعدادات المشروع على Vercel (Settings → Environment Variables).
4. **مهم:** قاعدة بيانات SQLite المحلية (`db/nexa.sqlite`) تُكتَب على نظام ملفات مؤقت في البيئات
   الخادمية بدون حالة (serverless) مثل Vercel، أي أن أي بيانات تضيفها من لوحة التحكم (خدمة جديدة،
   طلب عرض سعر...) **قد تُفقَد** بعد كل عملية نشر جديدة أو بعد فترة خمول. SQLite ممتاز للتطوير
   والاختبار المحلي، لكن للاستخدام الفعلي في الإنتاج انتقل إلى Supabase/PostgreSQL (انظر القسم التالي)
   **قبل** الإطلاق الفعلي، أو انشر على خادم تقليدي (VPS) حيث يبقى نظام الملفات دائمًا.

### على خادم تقليدي (VPS / Docker)

```bash
npm run build
npm run start   # يستمع على المنفذ 3000 افتراضيًا؛ ضعه خلف Nginx/Caddy مع HTTPS
```

## 7. الانتقال إلى Supabase / PostgreSQL

المشروع يستخدم SQLite حاليًا ليعمل فورًا بدون أي إعداد خارجي. للانتقال إلى Supabase (أو أي PostgreSQL):

1. أنشئ مشروع Supabase جديدًا، وشغّل محتوى `db/schema.sql` في محرر SQL الخاص به (الأنواع متوافقة تقريبًا
   1:1 — `TEXT`→`text`، `INTEGER` كـ boolean/عدد صحيح→`integer`/`boolean`، `DATETIME`→`timestamptz`).
2. استبدل `lib/db.ts` بعميل Postgres (مثل `@supabase/supabase-js` أو `pg` أو `drizzle-orm`)، مع الحفاظ
   على نفس تواقيع الدوال المستخدمة في `lib/data.ts` (`getPublishedServices`, `getServiceBySlug`, إلخ)
   حتى لا تحتاج لتعديل أي صفحة أو مكوّن واجهة.
3. حدّث كل نقاط API (`app/api/**/route.ts`) لتستخدم استعلامات SQL/عميل Postgres غير المتزامن (async)
   بدل استدعاءات `better-sqlite3` المتزامنة.
4. أضف `DATABASE_URL` أو مفاتيح Supabase (`SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`) إلى `.env`.

## 8. بنية المشروع (ملخّص)

```
app/[locale]/         الصفحات العامة (الرئيسية، الخدمات، المشاريع، من نحن، التواصل، عرض السعر...)
app/admin/             لوحة تحكم المدير (محمية بجلسة تسجيل الدخول)
app/api/                نقاط الوصول (REST) للخدمات، المشاريع، الأسئلة، الطلبات، الإعدادات، المصادقة
components/layout/      Navbar, Footer, LangSwitcher, WhatsAppButton
components/sections/    أقسام الصفحة الرئيسية وبقية الصفحات
components/admin/       عناصر لوحة التحكم (Sidebar)
lib/                    قاعدة البيانات (db.ts)، المصادقة (auth.ts)، الترجمة (i18n/)، طبقة البيانات (data.ts)
db/schema.sql           مخطط قاعدة البيانات الكامل
scripts/seed.ts         البيانات التجريبية الأولية
```

## 9. الأمان — ما تم تطبيقه بالفعل

- كلمات المرور مُشفَّرة بـ bcrypt، ولا تُخزَّن أبدًا كنص صريح.
- جلسات المدير عبر كوكي HTTP-only + JWT موقّع، غير قابلة للقراءة من JavaScript في المتصفح.
- كل مسارات `/admin/*` (عدا `/admin/login`) محمية على مستوى الـ layout، وتُعيد التوجيه لصفحة الدخول
  عند غياب الجلسة.
- كل نقاط API التي تُعدِّل بيانات (POST/PATCH/DELETE) تتحقق من الجلسة عبر `requireAdmin()`.
- التحقق من صحة كل المدخلات القادمة من النماذج عبر `zod` قبل الكتابة في قاعدة البيانات.
- تحديد نوع وحجم الملفات المرفوعة (5MB كحد أقصى، أنواع محددة فقط: PDF/صور/Word).
- حماية أساسية من الإزعاج (rate limiting بالذاكرة) على نماذج التواصل وعرض السعر وتسجيل الدخول —
  للإنتاج على نطاق واسع، يُستحسن استبدالها بحل موزَّع مثل Upstash Redis.
- لا توجد أي مفاتيح أو أسرار مكتوبة داخل الكود؛ كلها عبر متغيرات البيئة في `.env` (غير مرفوع لأي مستودع).

## 10. ملاحظات

- لا توجد أي بيانات وهمية منسوبة لعملاء حقيقيين — المشاريع التجريبية (عند إضافتها) تحمل وسم "مشروع تجريبي" بوضوح.
- لم تُخترَع أي أرقام (عدد عملاء، عدد مشاريع...)؛ قسم "شريط الثقة" يستخدم عبارات عامة كما طُلب.
- الأيقونات من مكتبة `lucide-react`؛ أيقونات العلامات التجارية (Instagram/Facebook/LinkedIn) أُزيلت من
  إصدارات المكتبة الحديثة لأسباب متعلقة بالعلامات التجارية، لذا استُخدمت أيقونات عامة بديلة في الفوتر —
  يمكنك استبدالها بشعارات SVG حقيقية بسهولة إن رغبت.
